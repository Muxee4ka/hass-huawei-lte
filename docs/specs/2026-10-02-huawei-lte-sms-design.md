# Форк huawei_lte с чтением SMS — дизайн

Дата: 2026-10-02. Статус: одобрена; уточнена по итогам чтения кода ядра (колесо, overlay, лицензия, диагностика, Python 3.14).

## Цель

Входящие SMS на Huawei HiLink-модеме (у нас E3372 в доме, через тоннель) должны
попадать в Home Assistant как события, чтобы их можно было пересылать (Telegram,
push) с фильтрацией рекламы. Штатная интеграция `huawei_lte` умеет только
отправлять SMS и считать их, текст не читает.

**Критерии успеха:**
- пришедшее на модем SMS в течение одного цикла опроса (30 с) появляется
  как событие `event.e3372_incoming_sms` с номером, текстом и датой;
- старые SMS (126 шт. на момент написания) не порождают событий;
- после установки форка существующая запись `huawei_lte`, все сущности E3372
  и их история остаются без изменений;
- blueprint пересылает SMS в выбранное действие с фильтром отправителей/слов.

## Решения и почему

| Решение | Почему |
|---|---|
| Форк ядровой `huawei_lte`, а не отдельная интеграция | Пользователь не хочет две интеграции; одна сессия к модему. |
| Только для себя, без PR в ядро (пока) | Решение пользователя. Код при этом не мешает апстриму. |
| Event-сущность, без события на шине и без сенсора «последнее SMS» | Так просили мейнтейнеры ядра в закрытых PR #166811/#166895; сенсор при нужде — шаблоном. |
| Публичный репозиторий, поддержка других HiLink «по мере возможности» | Ответ «1» на вопрос об аудитории; тестируем на E3372. |

Изученный прецедент: [`william-aqn/huawei_lte_extended`](https://github.com/william-aqn/huawei_lte_extended)
(отдельная интеграция поверх `runtime_data` ядра, событие на шине) — не берём.

## 1. Репозиторий и форк

- `Muxee4ka/hass-huawei-lte`, публичный, HACS custom repository.
- `custom_components/huawei_lte/` — копия `homeassistant/components/huawei_lte`
  из **колеса `homeassistant==2026.9.4` с PyPI** (не из git: только в колесе есть
  собранные `translations/*.json`, без которых custom-интеграция теряет имена
  сущностей); домен тот же, поэтому HA грузит форк вместо встроенной.
- Лицензия ядра — Apache-2.0: в репозитории `LICENSE` (Apache-2.0) и `NOTICE`
  с указанием, что это изменённая копия кода Home Assistant.
- Наши строки переводов (en, ru) лежат отдельно в `overlay/translations/*.json`
  и вливаются в `translations/*.json` и `strings.json` скриптом
  `scripts/apply_overlay.py` — после синка с ядром переводы не надо мержить руками.
- `manifest.json`: добавлен `"version"`; `requirements` не меняются
  (`huawei-lte-api==1.11.0`, `url-normalize==3.0.0`).
- **Первый коммит — копия ядра без правок.** Наши изменения — отдельными коммитами
  поверх; `git diff <первый коммит>` всегда показывает весь патч.
- `scripts/sync_upstream.sh <version>` — кладёт `huawei_lte` из колеса нужной версии
  в ветку `upstream` (там только чистое ядро + файл `UPSTREAM_VERSION`); дальше
  `git merge upstream` в `main` и `scripts/apply_overlay.py`; конфликты — руками.
- README: предупреждение, что форк перекрывает штатную интеграцию; откат —
  удалить из HACS и перезапустить HA.

## 2. Чтение SMS и событие

Файлы: новый `sms.py` (чистая логика, без HA и сети), новый `event.py`,
точечные правки `const.py`, `__init__.py`, `strings.json`, `translations/`.

**Опрос** — внутри существующего `Router.update` (SCAN_INTERVAL ядра, 30 с):
1. Ядро уже запрашивает `sms_count`; запоминаем пару `(LocalInbox, LocalUnread)`.
2. Список (`client.sms.get_sms_list`, страница 1, 20 шт., `BoxTypeEnum.LOCAL_INBOX`,
   сортировка по дате, новые сверху) запрашивается только на первом цикле или когда
   пара изменилась.
3. Новый ключ `KEY_SMS_SMS_LIST` идёт через ядровой механизм подписок: на него
   подписывается event-сущность. Ошибки «не поддерживается» / «нужна авторизация
   в unauthenticated mode» обрабатывает ядровой `_get_data` — ключ исключается с
   предупреждением, остальное работает.

Известное ограничение: если между двумя циклами одно SMS удалили вне HA, а другое
пришло, пара счётчиков не изменится и новое SMS будет замечено только при
следующем изменении счётчиков. Принимаем: окно 30 с, событие маловероятное.

**Новизна** (`sms.py`, класс `SmsTracker`):
- ключ сообщения — `(Index, Date, Phone)`;
- журнал последних 200 ключей, хранится в `Store`
  (`.storage/huawei_lte.sms_seen.<entry_id>`), переживает рестарт; файл удаляется при удалении записи;
- **первый запуск** (журнала нет): всё, что есть в модеме, записывается как виденное,
  событий нет;
- несколько новых за цикл отдаются от старых к новым;
- длинные SMS модем склеивает сам, сборка частей не нужна.

**Event-сущность** `event.<модем>_incoming_sms`:
- `event_types: ["received"]`, данные: `phone`, `text`, `date`, `index`;
- включена по умолчанию;
- **диагностика:** ключ `sms_sms_list` добавлен в редактируемые — тексты и номера
  SMS в выгрузку диагностики не попадают;
- `Router.update` работает в executor → новые сообщения передаются сущности
  dispatcher-сигналом (как ядровой `UPDATE_SIGNAL`).

## 3. Службы, автодействие, blueprint

**Службы** (`services.yaml`, `async_register_admin_service`, модем выбирается
необязательным `url` — как ядровые `suspend_integration`/`resume_integration`):

| Служба | Поля | Действие |
|---|---|---|
| `huawei_lte.sms_mark_read` | `index`: int или список | пометить прочитанными |
| `huawei_lte.sms_delete` | `index`: int или список | удалить |
| `huawei_lte.sms_delete_read` | — | удалить все прочитанные во входящих (все страницы) |

**Опция** `sms_after_receive` в существующем options flow ядра:
`nothing` (по умолчанию) | `mark_read` | `delete`. Выполняется после отправки
события; ошибка → предупреждение в лог, сообщение всё равно считается виденным.

**Blueprint** `blueprints/automation/huawei_lte/forward_sms.yaml` («Переслать SMS»):
- `sms_event` — event-сущность модема;
- `forward_action` — селектор action; в шаблонах доступны `phone`, `text`, `date`;
- `allow_senders` — если не пуст, пересылать только этих;
- `block_senders` — глушить этих;
- `block_keywords` — не пересылать, если текст содержит любое из слов;
- `mode: queued`.

## 4. Тесты, CI, релизы

`pytest` + `pytest-homeassistant-custom-component==0.13.367` (= HA 2026.9.4), **Python 3.14**.

| Тест | Покрывает |
|---|---|
| `test_sms.py` | первый запуск без событий, дедуп, сброс Index, лимит 200, порядок, Store |
| `test_event.py` | новое SMS → состояние/атрибуты; счётчики не менялись → нет запроса списка; «не поддерживается» → ключ исключён |
| `test_services.py` | три службы, выбор по `url`, `delete_read` по нескольким страницам |
| `test_options.py` | `nothing` / `mark_read` / `delete`; ошибка автодействия не даёт дубля |
| `test_blueprint.py` | blueprint валиден по схеме, фильтры работают |
| `tests/core/` | ядровые тесты `huawei_lte` из того же тега с поправленными импортами (`scripts/port_core_tests.sh`); неадаптируемые исключаются явно, с пояснением |

CI: `tests.yml` (push/PR, Python 3.14), `validate.yml` (HACS action + hassfest),
`upstream-watch.yml` (раз в неделю: если `huawei_lte` в свежем релизе ядра
изменилась — открыть issue).

Релизы: теги `v0.1.0`…, GitHub Release на каждый; `hacs.json` —
`"homeassistant": "2026.9.0"`; в README и релизе — «based on core 2026.9.4».

**Приёмка на живом модеме** (HA в квартире, E3372 в доме):
1. Установка через HACS, рестарт: все `sensor.e3372_*` на месте с историей,
   в логе только предупреждение о переопределении.
2. После первого запуска — ни одного события по старым SMS.
3. Тестовое SMS модему с самого себя через `notify.huawei_lte` (номер SIM — из
   модема/USSD) → появилось `event.e3372_incoming_sms`.
4. Blueprint с пересылкой в Telegram доставил тестовое SMS.
